\begin{abstract}
Real-time requirements written in Metric Temporal Logic are checked by translating their negation into a timed B\"uchi automaton (TBA) that a model checker such as UPPAAL or TChecker composes with the system. We evaluate a whole translation chain whose steps are verified in Rocq: a translation from MTL to clocked linear temporal logic and to a TBA, a pipeline of language-preserving optimization passes (synthesis and propagation of timing bounds, removal of contradictory transitions and dead resets, merging of clocks, transitions and locations), and an export that eliminates the disjunctive invariants UPPAAL cannot read. Each optimization pass preserves the timed-word language of every input TBA for any number of rounds, and the chain composes without hypotheses on the propositional backend. The chain is modular and compositional: each stage is stated against an interface, so Spot, or the whole front end, can be replaced by another translator, for instance a direct construction like CASAAL's, without changing the optimization and export theorems. The extracted code runs inside the translator \texttt{mtl2tba}; it calls Spot for the propositional automaton, and a default automatic mode chooses Spot's level, with a manual override that gains the few seconds the automatic choice spends. We compare the tool with CASAAL, an independent translator, on requirement patterns. On negated requirements the automata have the same size wherever both tools finish, and TChecker stores 28,555 states on ours against 30,890 on CASAAL's (fewer on 10 of 16 patterns, more on none). This advantage comes from the translation: disabling our optimizer does not change what TChecker stores, and the optimizer's effect is on output size (the nested automaton of seven levels shrinks from 10,930 to 5,105 transitions). In generation time the picture is mixed: with the right Spot setting ours is faster than CASAAL on nested requirements of five and six levels (1.3~s against 1.9~s at six), and slower on seven (15~s against 11~s) and eight (243~s against 74~s), where Spot, the replaceable part of the chain, dominates; the default automatic mode adds at most 5~s. We report these limits together with the verified rewritings that made the extracted code practical.
\end{abstract}
